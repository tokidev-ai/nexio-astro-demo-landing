How the pin works

scroll ──────────────────────────────────────────────────────────▶ │ enter │ │ pinned — end: "+=200%" │ │ release │ ├───────┼──────────────────────────────────────────────┼─────────┤ rail x: 0% ────────── scrub 1 ────────▶ −66% progress fill grows in lockstep with x
  • scrub: 1 — tied to the scrollbar with a 1s catch-up so it feels weighted rather than snapped.
  • This is the only pinned section on the page. Two would fight native scroll feel; the skill caps it at 1–2 and mobile punishes more.
  • ScrollTrigger.refresh() fires after fonts and images settle, or the pin length is computed against the wrong height.
  • The rail is a focusable region with a label, so keyboard users can arrow through it without a drag gesture.

Degradation

  • Reduced motion — no pin, no scrub. The section becomes exactly what you see above: a natively scrollable rail with snap points. Every panel stays reachable.
  • No JS — identical to the reduced-motion state. The markup is a plain overflow container; GSAP only ever upgrades it.
  • Below 768px — the pin is dropped entirely. Vertical-scroll hijacking on a phone is the single fastest way to make a site feel broken.
  • Panels stay in DOM order, so reading order and tab order match the visual sequence.
